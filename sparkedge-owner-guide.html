Firestore Collections — What's Stored Where
Firestore organizes data in "collections" (like folders) with "documents" (like files)
📂
clients collection
Stores every client ticket. Each document ID = the Ticket ID (SE-001, SE-002 etc.). Contains all ticket data: client name, project, payment stages, deliverables, timeline, files, progress. Written by admin.html when you click "Save to Firestore". Read by dashboard.html in real-time.
Read: dashboard.html Write: admin.html
📂
team collection
Stores all team members added via Team page in admin.html and docs.html. Each document ID = the member's id field. Contains name, role, email, password, permissions, status. This is how Pinkesh can log in from any device — his account lives here.
Read: admin.html + docs.html login Write: admin.html Team page
📂
settings collection — document: agency
Stores your agency settings: UPI ID, bank details, owner name, email, phone. When you save Settings in admin.html, this updates. dashboard.html reads this — so if you change your UPI ID, every client's payment modal updates automatically without touching any file.
Read: dashboard.html payment modal Write: admin.html Settings page
📂
vouchers collection — document: all
Stores all referral vouchers as a JSON list inside one document. Syncs when you create, use, or delete vouchers in admin.html.
Read + Write: admin.html Referrals page

Firebase Security Rules — IMPORTANT
If saving to Firestore fails, this is why

Go to console.firebase.google.com → Your project → Firestore Database → Rules tab. Your rules must allow reads and writes. Paste this:

rules_version = '2'; service cloud.firestore { match /databases/{database}/documents { match /{document=**} { allow read, write: if true; } } }
⚠️ Note: These are open rules — fine for your private use case since admin.html is password-protected. If you want extra security in future, rules can be tightened to require Firebase Auth. For now, this is correct for your setup.

HARDCODED_MEMBERS — What Is It and Why It Exists

Both admin.html and docs.html have a HARDCODED_MEMBERS array near the top of their JavaScript. This is a fallback safety net — if Firestore is unreachable (no internet, Firebase down), members in this array can still log in.

Pinkesh is currently hardcoded in both files. His Firestore entry will always take priority (Firestore wins over hardcoded for same IDs), but if Firestore fails, the hardcoded entry is the backup.

When to update HARDCODED_MEMBERS manually:
• When you add a completely new member you want to work even offline
• When you permanently remove someone (remove from array + Firestore)
• When someone's password changes (update in both places)

How to update it: Open admin.html (or docs.html) in VS Code / Notepad → find const HARDCODED_MEMBERS = [ → edit the array → save file → git push.

✅
Bug 1 — Team Members Only Worked on One Browser
❌ Was Broken
✅ Fixed Now
You added Pinkesh in admin.html on your laptop. His account was saved in YOUR browser's localStorage. He opened admin.html on his own phone — his password didn't work because his phone had empty localStorage.
Team members are now saved to Firestore. Pinkesh types his password on any device, any browser, anywhere in the world — it fetches from Firestore and works immediately.
How it was fixed: The saveMembers() function in admin.html was updated to be async and write to Firestore using batch.set(). The login function now checks Firestore directly if the local cache doesn't have the member. The toggleMemberStatus(), deleteMember(), and saveMember() functions were all made async with await saveMembers() calls. Same fix was applied to docs.html.
✅

14 — TROUBLESHOOTING
When Something Breaks — How to Fix It
!
"Firestore sync failed" toast appears when saving
Cause: Firebase security rules are blocking writes, OR no internet connection.
Fix Step 1: Check your internet. If fine, go to console.firebase.google.com → Your project → Firestore Database → Rules → Make sure rules say allow read, write: if true;
Fix Step 2: If rules are correct, try refreshing the page and saving again. The toast "Saved locally — Firestore sync failed" means your data IS saved locally and will sync when connection restores.
Most common issue
!
Pinkesh's password doesn't work on his device
Cause: Either Firestore sync hasn't completed yet, or his account is suspended, or there's a typo in password.
Fix: admin.html Team page → check if his status is "Active". Then check the password displayed matches what he typed (it's case-sensitive). If all correct, check Firestore console — see if his document exists in the team collection. If it doesn't exist there, re-save him from the Team page.
!
Client types their Ticket ID but gets "Ticket Not Found" error
Cause: The ticket doesn't exist in Firestore yet (only in localStorage), OR the ticket ID is spelled differently (e.g. SE-1 vs SE-001).
Fix: Open admin.html → open that ticket → click "☁️ Save to Firestore" → client refreshes → should work. Make sure the ticket ID in Firestore exactly matches what the client is typing.
!
Admin panel shows no tickets after opening on a new device
Cause: admin.html reads tickets from localStorage first, then tries to sync from Firestore. On a new device, localStorage is empty and the sync happens in background.
Fix: Wait 3–5 seconds after logging in — tickets load from Firestore automatically. If still not showing, use the ⬆ Import button and paste your last exported JSON to restore tickets to that device's localStorage.
!
Client dashboard shows old data / doesn't show latest update
Cause: You saved to localStorage but forgot to push to Firestore, OR there's a browser cache issue on client's device.
Fix: Go to admin.html → open ticket → click "☁️ Save to Firestore" (not just "Save locally"). Tell client to hard refresh their browser (Ctrl+Shift+R on PC, Cmd+Shift+R on Mac, or clear cache on phone).
!
Dashboard shows "Loading..." forever (never loads)
Cause: Firebase SDK not loading (network issue), OR Firestore rules blocking read, OR the ticket ID doesn't exist.
Fix: Open browser console (F12 → Console tab) → look for red error messages. Common ones: "Permission denied" = fix Firestore rules. "net::ERR_FAILED" = network issue. "app/duplicate-app" = page refresh needed.
!
Export button downloads but import on another device doesn't work
Cause: The JSON format is wrong (file was modified) or pasted incorrectly.
Fix: Open the downloaded JSON file in Notepad — it should start with {"tickets":[. Copy ALL the text (Ctrl+A, Ctrl+C). Go to Import modal → paste → click Import & Merge. Make sure you're pasting the full content including the opening and closing braces.
